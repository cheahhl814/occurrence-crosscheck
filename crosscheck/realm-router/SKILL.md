# realm-router/edna-crosscheck-realm-router

## Inputs
- `params.json` (from preflight; must have `realm` set).

## Outputs
- `routing.json` — `{realm, occurrence_sources, taxon_backbones, call_obis, call_worms,
  call_bio_oracle, env_source, env_column_prefix, env_layer_choice, qc_checks,
  missing_aphia_is_error}`.

## Procedure
```bash
python3 realm_router.py <params.json> <out_routing.json>
```
Pure lookup against `ROUTING_TABLE` (see PLAN §2 scope table). No network calls, no ambiguity — this is
the single source of realm branching for the whole skill (PLAN §4: "no downstream sub-skill contains
realm if-statements").

## Ask-user stop points

**SP1 — ON_LAND check scope for freshwater.** Evidence: PLAN §2 scope table says freshwater ON_LAND
applies "with riparian exceptions expected". Recommend: keep ON_LAND in freshwater's `qc_checks` but at
`warning` level only (never `error`), same bbox-membership proxy as marine. Decision (pinned intent,
implemented as documented): freshwater keeps ON_LAND, terrestrial omits it entirely.

**SP2 — WoRMS scope for freshwater (PLAN nuance vs. pinned battle-test contract).** Evidence: PLAN §2
says WoRMS "covers brackish/freshwater taxa where a marine history exists" (implying freshwater *could*
call WoRMS). The task's pinned battle-test explicitly requires freshwater runs to **never** call WoRMS.
Recommend: the pinned battle-test contract wins (it's the acceptance test this build is graded against).
Decision (pinned, and documented as a clarification in `realm_router.py`'s module comment, not a true
plan inconsistency — PLAN's own §9 acceptance criteria for the realm-matrix test says the same thing):
`call_worms = (realm == "marine")` only.

**SP3 — CMIP6 scenario support.** Evidence: PLAN §11.1 schema includes `env_scenario:
"present | CMIP6-SSP..."`. Recommend: support the field end-to-end (dataset ID construction already
handles `ssp1xx..ssp585`) but default to `present`/`baseline` unless the user asks for a projection.
Decision (pinned default): `present` is the default; CMIP6 scenarios are a pass-through, not
battle-tested in v1 (only `present` fixture used).

## Signature library

| stderr / evidence pattern | likely cause | fix |
|---|---|---|
| `unknown realm 'X'; expected one of ...` | `params.json.realm` has a typo or unsupported value | fix params.json / re-run preflight with a valid `--realm` |
| downstream sub-skill calls WoRMS/OBIS/Bio-ORACLE for a non-marine realm | a sub-skill bypassed `routing.json` and branched on realm itself | that sub-skill has a bug — realm-router is meant to be the ONLY realm branch point; grep for stray `if realm ==` outside `realm_router.py` |
| `routing.json` missing `call_obis`/`call_worms`/`call_bio_oracle` keys | routing.json was generated by an older/incompatible realm_router.py version | re-run `realm_router.py` from this skill version; do not hand-edit routing.json |
