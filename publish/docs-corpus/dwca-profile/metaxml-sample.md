# docs-corpus/dwca-profile — meta.xml conventions and full sample (Event Core + 3 extensions)

This is the exact shape of meta.xml that `scripts/dwca_core.py` generates. Verified against
the Darwin Core Text Guide (http://rs.tdwg.org/dwc/terms/guides/text/index.htm) and the
eDNAbridge expected_meta.xml worked example.

## Rules

- Root: `<archive xmlns="http://rs.tdwg.org/dwc/text/" metadata="eml.xml">`.
- Exactly one `<core>`; extensions as sibling `<extension>` elements.
- `rowType` must be the fully-qualified term URI.
- Core `<id index="N"/>` points at the core's unique id column (occurrenceID or eventID).
- Extension `<coreid index="N"/>` points at the extension's link column (occurrenceID / eventID).
- Column order in meta.xml `<field>` entries MUST match the CSV column order exactly (0-based index).
- `fieldsEnclosedBy="&quot;"` for quoted CSV; keep `ignoreHeaderLines="1"`.
- `location` paths are zip-relative (e.g. `event_core.txt`, `occurrence.txt`).

## Full sample generated by this skill

```xml
<?xml version="1.0" encoding="UTF-8"?>
<archive xmlns="http://rs.tdwg.org/dwc/text/" metadata="eml.xml">
  <core encoding="UTF-8" fieldsTerminatedBy="," linesTerminatedBy="\n"
        fieldsEnclosedBy="&quot;" ignoreHeaderLines="1"
        rowType="http://rs.tdwg.org/dwc/terms/Event">
    <files><location>event_core.txt</location></files>
    <id index="0"/>
    <field index="1" term="http://rs.tdwg.org/dwc/terms/parentEventID"/>
    <field index="2" term="http://rs.tdwg.org/dwc/terms/eventID"/>
    <!-- ... -->
  </core>
  <extension encoding="UTF-8" fieldsTerminatedBy="\t" linesTerminatedBy="\n"
             fieldsEnclosedBy="&quot;" ignoreHeaderLines="1"
             rowType="http://rs.tdwg.org/dwc/terms/Occurrence">
    <files><location>occurrence.txt</location></files>
    <coreid index="0"/>
    <field index="0" term="http://rs.tdwg.org/dwc/terms/occurrenceID"/>
    <!-- ... -->
  </extension>
</archive>
```

The validator treats structurally-malformed meta.xml (bad indices, missing rowType, wrong
location) as an ERROR — this is one of the local structural checks in ../gbif-data-validator/.
