# Sub-skill: gbif-publish

## Inputs / Outputs contract

| Artifact | Source | Required |
|---|---|---|
| `<run-dir>/enriched.parquet` | edna-crosscheck (§11.2) | yes |
| `<run-dir>/params.json` | run manifest (§11.1) | yes |
| `work/gate_report.json` | preflight-publish | yes (must be `gate_a == passed`) |
| `<work>/out/gbif/dataset_gbif_dwca.zip` | this sub-skill | — (produced) |
| `work/publish_commands.sh` | appended IPT/eDNAbridge upload command | — (appended) |

Implementation: `scripts/gbif_publish.py` (and the shared `scripts/dwca_core.py` writer).

## Procedure

1. **Re-check gate (a).** Read `work/gate_report.json`; abort if `gate_a != "passed"`.
   (Belt-and-braces: preflight is the gate owner; this leg must not trust stale state.)
2. **Map rows to DwC** (occurrence core):
   - `occurrenceID` = stable hash of (eventDate, decimalLatitude, decimalLongitude, scientificName, ASV id).
   - `basisOfRecord` = `MaterialSample` (eDNA per GBIF DNA-derived publishing guide).
   - `organismQuantity` / `organismQuantityType` ("DNA sequence reads") / `sampleSizeValue` /
     `sampleSizeUnit` — reads columns when present.
   - `scientificName`, `acceptedScientificName` → `scientificName`/`scientificNameID` mapping:
     `scientificNameID` left empty for GBIF (GBIF may warn; OBIS is where it gates).
   - `gbif_taxonKey` → `taxonID`; `taxon_match_status` → `identificationRemarks` notes;
     `verbatimIdentification` keeps the original name.
   - Coordinates/depth/date pass through; `associatedSequences` from `associatedSequences`
     column if present.
3. **DNA-derived data extension** (`dna_derived_data.txt`): `occurrenceID` + the §11.2-derived
   DNA terms (`DNA_sequence` from `dna_sequence`/`asv_sequence` column when present; primer/
   pipeline constants from the manifest's `marker` and fixed defaults; env_* MIxS ENVO classes
   chosen by realm == marine). Linked by `occurrenceID`.
4. **eMoF** (optional): only when `env_bio_*` columns are present (marine runs) — one row per
   (occurrence, env layer), Bio-ORACLE values slot in as measurementOrFact rows.
5. **meta.xml + eml.xml**: generated by `dwca_core.build_meta_xml` / `build_eml`
   (bbox from manifest, title from manifest title or skill default, EML 2.1.1 GBIF profile).
6. **Zip** → `<run>/..._gbif_dwca.zip` via `dwca_core.build_dwca_zip` (deterministic order,
   `metadata="eml.xml"` declared).
7. **Append upload command** to `work/publish_commands.sh`:
   ```bash
   Rscript -e 'eDNAbridge::ipt_upload_and_publish(archive="<zip path>", ipt_url="https://YOUR.IPT/")'
   ```
   (Reference path per docs-corpus/ednabridge-conv — the user executes it; this skill never does.)
8. Write `work/gbif_build_report.json` (row counts, file inventory, sha256).

## Interpretation Guidelines

- **GO**: zip exists; row count in zip == row count after sign-off filtering; validation next.
- **GO-WITH-WARNINGS**: warning-level issues acceptable (PLAN §6) — e.g. unresolved taxonomy rows
  (they were already gated through `qc_flags`/sign-off).
- **NO-GO**: gate (a) not passed, or zero publishable rows after applying `excluded` filter.

## Ask-user stop points

| SP | Trigger | Resolution record |
|---|---|---|
| SP-G1 | Archive build fails validation internally | Abort; user fixes upstream data. Autonomous mode: abort with report. |
| SP-G2 | eDNAbridge available vs plain archive | v1 pinned: always emit ready-to-run eDNAbridge command; our zip is the artifact. |
| SP-G3 | `excluded` rows present | Drop them silently with a count in the build report (explicit user decision already recorded in the TSV). |

## Troubleshooting — Signature library

| Signature | Likely cause | Suggested fix |
|---|---|---|
| `GATE-A still BLOCKED` | Stale gate report | Re-run `pixi run publish-preflight`. |
| `KeyError: occurrenceID` | Internal bug, not user data | Run `pixi run test-smoke`; file a debug-report.md. |
| `pyarrow` missing | Env not installed | `pixi install`. |
| `UnicodeEncodeError` writing occurrence.txt | Non-UTF8 names in source | Upstream normalization; do not strip characters silently. |
| `zipfile` entry missing at validation | meta.xml location mismatch | Check `dwca_core.build_meta_xml` file keys vs zip contents. |
